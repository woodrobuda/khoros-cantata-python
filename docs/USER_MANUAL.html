Khoros/Cantata Python — User Manual

This manual is written for someone who can use a computer and understands simple ideas such as a file, a folder, and a program. You do not need to know C or the original Khoros system.

1. What this program is

Cantata was a visual programming system. A user placed processing boxes, called glyphs, on a workspace and connected them with lines. Data moved from one box to the next.

This project keeps that basic idea, but the working engine is Python. The old Khoros executable is not required for the supported native operations.

Important: A historical workspace may name an old Khoros program. This release does not secretly start that program. If a Python-native replacement is not registered, the run stops instead of pretending the old program ran.

2. Installation

Use Python 3.11 or newer. NumPy is required for the numerical functions. From the release directory:

python -m pip install numpy

For testing, also install pytest:

python -m pip install pytest

3. First commands

See the recovered test collection

python -m khoros_cantata.cli inventory

This reports the number of historical test suites, scripts, result files, and test-data files.

Run the numerical checks

python -m khoros_cantata.cli check

A successful run prints eleven checks with the word PASS.

Inspect a workspace

python -m khoros_cantata.cli inspect historical_workspaces/datamanip/examples/workspaces/kclip/clipout.megaclip.wksp

The command lists the glyphs and connections. This is useful when you want to understand an old workflow before running it.

4. Explicit use cases

Use case A — Understand an old image workflow

  1. Choose a .wksp file.
  2. Run the inspect command.
  3. Read the listed glyphs from top to bottom.
  4. Look at the connections to see where data goes.

This is useful when the old application is gone but the workspace file remains.

Use case B — Check whether numerical behavior still works

  1. Run python -m khoros_cantata.cli check.
  2. Look for eleven PASS results.
  3. If a test fails, keep the output. It tells a programmer which behavior needs attention.

The checks cover FFT behavior, convolution, clipping, arithmetic identities, and sine-wave generation from recovered Khoros source semantics and historical test material.

Use case C — Read a historical VIFF file

from khoros_cantata.viff import read_viff

image = read_viff("my_image.viff")
print(image.segments.keys())

The returned object keeps the historical data segments instead of throwing away their metadata.

Use case D — Run a supported workspace in Python

from pathlib import Path
from khoros_cantata.workspace_runtime import HistoricalWorkspaceParser, WorkspaceExecutor, example_registry

path = Path("historical_workspaces/datamanip/examples/workspaces/kclip/clipout.megaclip.wksp")
old_graph = HistoricalWorkspaceParser().parse(path)
engine = WorkspaceExecutor(example_registry())
result = engine.execute(old_graph)
print("Completed", len(result.nodes), "nodes")

This uses the Python-native operator registry. It does not call the historical Khoros executable.

Use case E — Build a small new Python workflow

from khoros_cantata.workspace_runtime import NativeOperatorRegistry

registry = NativeOperatorRegistry()
registry.register("MYBOX", "double", lambda params, inputs: {"o": inputs["i"] * 2})

A programmer can then connect this operator to a restored workspace or build a new graph using the core kernel.

5. Understanding results

PASS means the implemented behavior matched the test used for that check.

Source-contract closed means the recovered source tells us what the software was supposed to do, but the original executable was not available for a direct comparison.

Native baseline means a Python implementation surface exists, but more historical evidence is needed before claiming behavioral equivalence.

6. Common questions

Do I need Khoros? No for the Python-native code in this release.

Can every old workspace run? No. A workspace can depend on an operator or external data that has not yet been reconstructed.

Is this the original Khoros source? No. It is a Python compatibility implementation based on recovered source evidence.
